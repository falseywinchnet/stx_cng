# Portable Huffman reconstruction merges

This experiment tests a first-party portable implementation of the binary merge
used in bottom-up, PivCo-style Huffman reconstruction. The retained matcher and
compact length table are unchanged. It is a primitive study, not a complete
entropy decoder or a new CNG format.

## Construction

A node's bitmap interleaves two previously reconstructed byte sequences. For each
8-output-byte group, the candidate loads up to 8 valid bytes from each input,
then expands each packed sequence into the byte positions selected by the bitmap.
A byte at input rank `r` belongs at destination `d`; its displacement is `d-r`.
Within either sequence these displacements are nondecreasing. Moving selected
bytes by 4, then 2, then 1 byte positions therefore preserves order and avoids
colliding live bytes. Unused input bytes are masked before these stages.

`merge_lanes` expresses the two expansions as an array of two 64-bit words. Fixed
mask/shift loops let LLVM use 128-bit vector instructions without intrinsics.
The final operation combines the expanded words. Pure groups use an 8-byte copy;
short inputs and output tails access only their supplied spans. The helper is a
prepared-run kernel: the caller must establish bitmap populations, counts and
non-overlap before entry.

The alternatives retain scalar selection, indexed byte selection, independently
shifted words, and separate scalar expansion. No external implementation code is
copied. The conceptual reference is the [PivCo Huffman paper](https://marcinzukowski.github.io/pivco-huffman/paper-1.0/ph.html),
whose complete decoder also needs flat-subtree and constant-child operations.

## Measurements

Build: non-Apple LLVM 23.1.2 on the selected M4 host; execution: Apple A18 Pro.
Seven measured trials after one warmup, rotating method order per packet and
trial. Each cell below sums per-packet medians in milliseconds. Allocations,
Huffman construction, partition preparation, flat-subtree decoding and output
comparison are outside the timer. Constant children are materialized in advance;
no constant-child specialization is credited. All methods process identical
prepared runs, not outputs generated by preceding timed merges.

|---|---:|---:|---:|---:|---:|
| Initial bytewise loader | 468.47 | 420.37 | 467.32 | 460.76 | — |
| Explicit full-word loader | 479.32 | 304.88 | 321.87 | 271.52 | 207.72 |
| Same binary repeated | 459.45 | 292.07 | 308.49 | 260.00 | 199.93 |
| Bounded 4/2/1-byte tail loader | 490.23 | 308.24 | 325.74 | 265.45 | 205.89 |

The final paired expansion takes 42.00% of its paired scalar baseline time, but
10 of 2,953 packets are slower. The earlier full-word version takes 43.34% and
43.51% on its two runs. The tail rewrite simplifies generated code; these runs
do not establish a repeatable standalone speed gain over that version.

All runs pass 73,984 deterministic bitmap/length fixtures and exact comparisons
for 2,953 corpus preparations. Those preparations contain 249,948,888 original
symbols, 75,526 binary merges, and 13,145 constant children. Their non-flat binary
merges produce 883,150,653 bytes: **3.5333 output bytes per original symbol**.
That repeated work is a material obstacle to beating the current complete
Huffman decoder. These kernel results do not establish such a win.

## Source-level access accounting

Across the corpus, binary merges account for:

- 110,426,285 bitmap bytes and 883,150,653 output bytes;
- 883,150,653 selected input bytes in the scalar formulation;
- 1,710,165,829 input bytes loaded by the bounded word formulations;
- 103,446,580 mixed groups and 6,914,521 pure groups.

Each mixed group accesses 9 selector bytes in the indexed/word formulations,
49 mask/count bytes in separate expansion, or 65 mask/count bytes in paired
expansion. Paired masks occupy 16 KiB, with a separate 2,304-byte selector table.
These are source-level byte counts, **not measured DRAM traffic**: cache reuse,
load coalescing, stack spills and instruction fetch are excluded. The indexed
assembly also materializes a 16-byte temporary on the stack. No hardware-counter
memory-bandwidth claim is made. Complete-decoder scratch requirements remain
unmeasured; the probe's preallocated per-node vectors are not a production
workspace design.

## Assembly and retained revisions

`merge_first.cpp`/`probe_first.cpp` retain the initial four-method experiment.
`merge_second.cpp` with `probe.cpp` retains the full-word five-method experiment.
`merge.cpp` with `probe.cpp` is the final bounded-tail revision. All use the
recorded 12-bit exact Huffman construction; no reference-induced 11-bit cap is
applied here.

Final arm64 assembly uses full-word loads and paired `and`/`eor`/`shl`/`orr`
operations. Strict x86-64 baseline assembly uses SSE2 `pand`/`pxor`/`psllq`/`por`;
there are no byte-shuffle intrinsics or wider-register requirements. Its final
8-bit expansion is partially combined with scalar lane reduction. x86-64 was
inspected, not executed. Big-endian behavior is expressed but unexecuted.

The initial x86 assembly used the compiler's macOS default target with only
`-msse2 -mno-avx`; that did **not** disable SSE4.1. It is preserved as such, not
baseline SSE2 evidence. The second and final builds explicitly disable SSE3,
SSSE3, SSE4.1, SSE4.2 and AVX, and select generic x86-64. Earlier study assembly
made with the weaker flags must not be credited as baseline SSE2 without being
regenerated and inspected.

An attempted file transfer before the third run failed; the old binary ran
again. That complete record is retained as `second-repeat`, not attributed to
the tail rewrite. The final run followed a successful transfer and binary hash
comparison. Timing changes between separate runs also include ambient variation.
